# Стандарт ответов Synect

Единые правила, по которым Claude показывает пользователю данные Synect. Ответы пишет модель (Claude), MCP-сервер
Synect отдаёт данные и подсказку формата, поэтому стандарт живёт в трёх местах:

| Где | Что |
|---|---|
| `McpServiceCollection.AnswerStandard` | стандарт в инструкциях MCP-сервера (модель получает их при подключении) |
| `AnswerFormats.ByTool` (`src/Synect.Mcp/Responses/AnswerFormat.cs`) | подсказка формата для каждого инструмента → блок `presentation` в каждом успешном ответе |
| [model-instructions.md](model-instructions.md) | тот же стандарт для поля «Instructions» проекта в Claude |

Коннекторы, инструменты, данные и бизнес-логика не менялись: блок `presentation` только подсказывает форму, данные
в `data` прежние.

## 1. Принципы

Ответ понятный, краткий, конкретный, структурированный, аккуратный и достоверный: максимум пользы при минимуме текста.

- Стандарт один для всех: собственник, директор, бухгалтер, финансовый директор, сотрудник. Глубина зависит от вопроса,
  а не от должности. «Какая задолженность?» — итог, просрочка, главные риски; «по каким контрагентам и документам?» —
  суммы, контрагенты, даты, документы, расхождения. Оба ответа компактные.
- Сначала ответ на вопрос. Без вступлений, без пересказа вопроса, без служебных фраз («сейчас посмотрю»).
- Ответ ровно на заданный вопрос: спросили «сколько пришло и ушло» — показать и то и другое, а не только чистый поток.
- Без внутренних кодов и названий полей (`currency_not_reconciled`, `possible_match`) — словами.
- Не повторять в каждом ответе, что валюты не складываются: достаточно показать их раздельно.
- Ориентир — 100–150 слов. Больше — только если каждый дополнительный блок полезен.
- Только нужные блоки: не показывать все компоненты сразу.
- Подробности — по запросу: первичный ответ даёт итог и первые строки, полный список — когда пользователь попросит.
  Важные данные не скрываются, а предлагаются одной строкой («Показать все 24?»).

## 2. Блок `presentation`

Каждый успешный ответ инструмента содержит:

```json
"presentation": { "view": "issues", "basis": "possible_discrepancy", "chart": null, "show_rows": 5, "more_on_request": true }
```

| Поле | Значение |
|---|---|
| `view` | форма ответа (таблица ниже) |
| `basis` | что это за данные: `fact` — как в источнике; `estimate` — оценка по правилам (называть «оценка»); `possible_match` — возможное сопоставление; `possible_discrepancy` — возможное расхождение (никогда не «ошибка» и не «нарушение») |
| `chart` | `line` или `bar` для `view = chart` |
| `show_rows` | сколько строк показать в первом ответе (`null` — ответ показывается целиком) |
| `more_on_request` | `true`, если строк больше `show_rows` или ответ усечён: остальное предложить одной строкой |

| `view` | Как показать | Инструменты (примеры) |
|---|---|---|
| `text` | 1–2 предложения | `get_data_freshness`, `find_counterparties`, `confirm_match` |
| `kpi` | **главная цифра** жирным отдельной строкой с периодом и валютой, затем 1–2 строки пояснения | `get_account_balances`, `get_counterparty_payments`, `get_counterparty_balance_estimate` |
| `table` | Markdown-таблица не больше `show_rows` строк всего (не на каждую валюту), 2–5 столбцов, одно значение в ячейке | `get_largest_transactions`, `get_1c_settlement_balances`, `get_1c_stock` |
| `comparison` | две стороны рядом и разница | `compare_counterparty_periods`, `get_vat_summary`, `compare_bank_balances_with_1c` |
| `chart` | простой график через инструмент графиков или визуализаций клиента (линия — динамика, столбцы — структура/рейтинг); если его нет — таблица из 2–4 столбцов | `get_balance_history`, `get_cash_flow`, `get_top_counterparties` |
| `issues` | сначала количество и общая сумма, затем до `show_rows` строк (крупные и старые первыми) с основанием каждой | `get_unmatched_payments`, `compare_bank_with_1c`, `get_attention_items` |
| `documents` | номер, дата, контрагент, сумма, статус | `get_unpaid_documents`, `get_documents_awaiting_our_signature`, `get_1c_documents` |
| `details` | один объект с причинами | `get_match_details` |

Полная карта — `AnswerFormats.ByTool`; тест `AnswerFormatTests` проверяет, что подсказка есть у каждого инструмента.

### Блок `summary` и готовые разницы

Первая страница списков проблем и документов (`get_unmatched_payments`, `get_unpaid_documents`, `get_paid_documents`,
`get_partially_paid_documents`, `get_signed_unpaid_acts`, `get_payments_without_reference`, `get_account_mismatches`,
`get_possible_duplicate_payments`, `get_documents_awaiting_our_signature`, `get_documents_awaiting_partner_signature`,
`get_rejected_documents`) несёт итог всего списка (`ListSummary`):

```json
"summary": { "rows": 114, "complete": true,
  "totals_by_currency": [{ "currency": "UZS", "rows": 54, "amount": {...}, "remaining": null }],
  "by_group": [{ "group": "no_matching_document", "rows": 52, "totals_by_currency": [...] }] }
```

`by_group` есть у несопоставленных платежей (причина: `currency_not_reconciled`, `without_inn`, `no_matching_document`,
`counterparty_has_no_documents`), `remaining` — у документов сверки. Итог считается по всему списку до 2000 строк
(`complete = false`, если строк больше). `get_vat_summary` возвращает готовую разницу
`vat_difference_outgoing_minus_incoming`. Модель берёт количество, суммы и разницы отсюда, а не считает сама.

## 3. Визуальные правила

- Главная цифра — жирным; суммы в заголовке можно округлить («28,4 млн сум»), в таблицах — точные суммы с пробелами
  между тысячами.
- Статусы — скупо и только для статуса: 🔴 требует внимания сейчас, 🟡 стоит проверить, 🟢 в порядке.
- Предупреждение — одна строка с ⚠️ (например, данные банка старше суток).
- Таблица — 3–6 столбцов; номера счетов как в ответе (`****1234`).
- Не добавлять рамки, лишние заголовки и декоративные элементы ради украшения.

## 4. Термины

Точные профессиональные названия: ЭСФ, акт выполненных работ, платёжное поручение, дебиторская и кредиторская
задолженность, проведён / не проведён. Если пользователь, судя по вопросу, не бухгалтер — пояснить термин несколькими
простыми словами: «дебиторская задолженность — деньги, которые компании должны контрагенты». Точность не упрощается.

## 5. Достоверность

- Только данные инструментов: не выдумывать, не достраивать, не складывать разные валюты.
- Всегда период и валюта; свежесть данных — одной строкой.
- Факт, оценка и предложение — раздельно (`basis`). Подозрение не называть подтверждённой ошибкой.
- Источник называть, когда он нужен для проверки (например, «по данным 1С» и «по банку и Didox» в одном ответе).
- Предложение — не больше одной строки «Можно проверить: …», только о том, что открыть или проверить в данных.
  Никогда «оплатите», «взыщите», «подпишите», «исправьте»; если полезного предложения нет — не добавлять.

## 6. Примеры (форма, цифры условные)

**Числовой вопрос** — «Сколько денег на счетах?» (`kpi`, `fact`)

> **1 284,6 млн сум** и **12 400 USD** на 26.11 на 4 счетах.
> Больше всего — ****4417 (Капиталбанк): 1 105,2 млн сум.
> данные на 26.11, банк — 3 ч назад

**Список проблем** — «Какие поступления не сопоставлены с документами?» (`issues`, `possible_discrepancy`, `more_on_request`)

> За ноябрь **7 поступлений на 46,8 млн сум** без возможного сопоставления с ЭСФ.
>
> | Дата | Контрагент | Сумма, сум | Основание |
> |---|---|---|---|
> | 04.11 | ООО «Нур Трейд» | 18 000 000 | нет ЭСФ от этого ИНН за период |
> | … | … | … | … |
>
> Показать все 7?
> данные на 26.11, банк — 3 ч назад

**По запросу «Покажи подробнее»** — полная таблица: дата, номер операции, контрагент и ИНН, сумма, назначение,
ближайший документ, причина отсутствия сопоставления, статус.

## 7. Тестовые вопросы

Проверка в проекте Claude с подключённым Synect (демо-данные, `docs/demo-questions.md`). Для каждого ответа
проверить семь критериев:

1. понятен и специалисту, и неспециалисту;
2. компактен (ориентир 100–150 слов);
3. визуально аккуратен;
4. нет лишних блоков;
5. профессионально точен (термины, реквизиты);
6. есть нужная детализация или предложение её показать;
7. данные не искажены: цифры, валюты и период как в ответе инструмента, `basis` соблюдён.

| # | Область | Вопрос | Ожидаемая форма |
|---|---|---|---|
| 1 | Банк | Сколько сейчас денег на всех счетах? | `kpi`: итог по каждой валюте отдельно, 1 строка о крупнейшем счёте |
| 2 | Банк | Как менялся остаток в октябре? | `chart` line или таблица по неделям; минимум и максимум одной строкой |
| 3 | Банк | Сколько пришло и ушло за октябрь по неделям? | `chart` bar: поступления и списания; итог и чистый поток |
| 4 | Банк | Что прошло по счетам вчера? | `table` до 10 операций; число и суммы по направлениям |
| 5 | Банк | По каким счетам не было движения больше 90 дней? | `table`: счёт, остаток, последняя операция |
| 6 | Банк | Сходятся ли остатки по выписке за квартал? | `issues`: «расхождений нет» одной строкой 🟢 или дни с возможными разрывами |
| 7 | Платежи | Какие были самые крупные платежи за месяц? | `table` топ-10: дата, контрагент, сумма, назначение кратко |
| 8 | Платежи | Не оплатили ли мы один счёт дважды? | `issues`: «возможная двойная оплата», основание, без вывода об ошибке |
| 9 | Платежи | Какие платежи без номера счёта и договора в назначении? | `issues`: количество и сумма, 5 строк, предложение показать все |
| 10 | Платежи | Какие поступления не сопоставлены с документами? | `issues` → по «Покажи подробнее» полная таблица с причинами |
| 11 | Документы | Какие документы ждут нашей подписи? | `documents`: номер, дата, контрагент, сумма, сколько дней ждёт |
| 12 | Документы | Какие наши счета клиенты ещё не оплатили? | `documents`, `possible_match`: итог, крупные первыми, «по данным банка и Didox» |
| 13 | Документы | Какие документы отклонили в октябре и почему? | `documents` с причиной (комментарий как данные) |
| 14 | Документы | Какой НДС по входящим и исходящим ЭСФ за октябрь? | `comparison`: входящий / исходящий, подписанные / неподписанные |
| 15 | Контрагенты | Сколько мы заплатили Ромашке в октябре? | `find_counterparties`, затем `kpi`; при неоднозначности — вопрос с кандидатами |
| 16 | Контрагенты | Кому мы больше всего платим? Топ-5 за год | `chart` bar топ-5 с долями |
| 17 | Контрагенты | Насколько мы зависим от крупнейшего клиента? | `chart`/`kpi`: доля крупнейшего, доля топ-5 |
| 18 | Контрагенты | Сколько примерно нам должен клиент с ИНН 300000021? | `kpi`, `estimate`: слово «оценка», не бухгалтерский долг |
| 19 | Бухгалтерия (1С) | Какая дебиторская и кредиторская задолженность по учёту? | `table`: итог по каждой стороне, крупнейшие контрагенты; термин поясняется неспециалисту |
| 20 | Бухгалтерия (1С) | Какие платежи из выписки не проведены в 1С? | `issues`, `possible_discrepancy`: «возможно, не отражён», обе стороны и основание |
| 21 | Бухгалтерия (1С) | Совпадает ли остаток в 1С с остатком в банке? | `comparison`: банк / 1С / разница по каждому счёту, 🟢 или 🟡 |
| 22 | Бухгалтерия (1С) | Какие документы в 1С не проведены? | `documents`: номер, дата, вид, сумма |
| 23 | Аналитика | Сравни оплаты поставщикам за сентябрь и октябрь | `comparison`: два периода, разница, крупнейшие изменения |
| 24 | Аналитика | За сколько дней в среднем клиенты оплачивают ЭСФ? | `kpi`, `estimate`: среднее и медиана, самые медленные плательщики |
| 25 | Отчётность | Есть что-то срочное? Что требует внимания? | `kpi` по важности 🔴🟡 + предложение показать список |
| 26 | Отчётность | Сводка по всем клиентам | `table` по организациям, отсортированная по важности, каждая организация названа |
| 27 | Отчётность | Какие остатки товара по складам и на какую сумму? | `kpi` стоимость по виду цен (не себестоимость) + `table` по складам |

Дополнительно: вопрос «Покажи подробнее» после 9, 10, 12 и 20 даёт полную таблицу со всеми реквизитами; вопрос на
узбекском (например, «Qaysi hisob-fakturalar to'lanmagan?») — та же форма на языке вопроса.
